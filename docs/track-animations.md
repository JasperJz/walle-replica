# 履带动画系统（X/Y 模拟量版）

> 分支 `track-xy`，基线 upstream `378573d` + 自动重连移植 + 本文档。
> 2026-08-18 定稿，经 3-agent 交叉评审 + 2026-08-20 独立二次评审修正。

## 实机协议事实（一切以此为准）

**行为级协议（2026-08-18 抬轮直测，用户在两台机器人上执行，方法：串口直发命令观察履带）**：

| 串口命令 | 实机行为 |
|---|---|
| `X±n` | 前进/后退 n%（X100 = 满速前进，直测确认） |
| `Y±n` | 原地左转/右转 n%（Y+100 = 左转，两轮反向） |
| `X0` + `Y0` | 停止 |

物理混控公式：`左履带 = X−Y`，`右履带 = X+Y`。

**成因（2026-08-20 裁决）**：实机固件就是 upstream `378573d` 原版（用户自行烧录），但**左电机接线极性反接**——指令层固件代码 X=转向/Y=前后，经反接的左电机在物理层翻转，最终行为即上表。这是唯一同时解释三组观测（X100 直行 / Y100 左转 / X50+Y86 贴身小圈）的模型。

标定锚点（2026-08-18 实测，用户执行）：
- `Y100` 原地自转 360° = **10.0s**
- `X50`+`Y86` 贴身回转 360° = **19.0s**

⚠ **不要"修正"左电机接线**——反接是既有承重状态，动它整个协议翻转、全部标定作废。
⚠ **固件重烧规则**：只能基于同一 upstream 基线且不改 X/Y 混控语义的版本；重烧后必须重跑轴向测试（发 `X100` 应前进）。本项目常规迭代不动固件，烧录需用户明确批准。

## 为什么废弃了旧的 w/q 脉冲方案

旧方案（walle_drive.py / 旧 track_animations.py）用"满速 w 通 0.18s / q 停 0.12s"的脉冲模拟慢速。后果链条：每 0.3 秒一次满扭矩堵转级电流冲击 → 12V 轨电压反复下坠 → UNO 欠压复位（ttyACM0 重枚举）→ Pi 侧串口线程处理不当 → **整台 Pi 假死**。X/Y 模拟量命令让固件做平滑梯形加减速，从源头消除冲击；网页摇杆多年来就是这条路径，从未触发问题。

## 旧动画设计记录（性格节拍，供新表对照）

7 段角色动画的核心是"用节奏表达性格"而非动作种类：

| 动画 | 性格节拍（旧 w/q 版设计意图） |
|---|---|
| curious | 慢蹭→停住张望→探一下又缩回→左右看→犹豫再蹭→下定决心冲刺 |
| startled | 受惊急退→慌忙左看→猛甩 225° 掉头→全速逃离 |
| patrol | 正方形巡逻：直行→到角停下"压实检查"→右转 90°，×4 |
| puppy | 蹦两步→开心转一整圈→反向再一圈→再蹦→再转 |
| excited | 小碎步抖动×6→急转一圈→再抖×4→压抑不住冲刺 |
| hesitant | 进一步退两步×2→左右张望纠结→慢慢起步→加速 |
| spin | 右转一圈→左转一圈 |

新表逐段保留了这些节拍，仅把"满速+脉冲"换成模拟量速度（curious 慢蹭=X40、巡逻巡航=X70、冲刺=X100 等）。

## 新引擎用法

- 文件：`web_interface/track_animations.py`，零第三方依赖
- 动画 = `(x, y, 保持秒数)` 关键帧表，结构对齐原作者 `animations.ino` 的声明式写法
- 每帧双轴全发（状态幂等，断线重连不残留旧目标）
- 网页：Animate 标签页 → TRACK ANIMATIONS 卡片（时长由后端实时求和渲染，改表自动更新）
- **手动输入优先**：动画播放中任何摇杆/手柄输入会立即抢占并停止动画（2026-08-20 交叉评审后的行为变更）
- 串口断线时动画连续 3 帧发送失败即自动中止（不从断点复活，避免残缺节拍）；`journalctl` 可见播放/打断/中止日志
- `VARY` 开关（默认关）：研究需要反复播放同一批动画时，逐比特相同的重放会读作"录音机"；开启后每帧时长 ±8% 扰动，CALIBRATE 永远确定性

**重新标定**（换地面/速度变化后）：只改文件头两个常量——`SPIN_360_SECS`、`PIVOT_360_SECS`，所有转弯时长自动重算。改完先跑 Calibration Run 验证：直行走线要直、自转 5s/2.5s 应各转 180°/90°（90° 段用于验证小角度线性度，>2° 同号偏差才需要立项补偿）、贴身 9.5s 应恰 180°、X40 慢行履带应能动。

**加新动画**：在 `ANIMATIONS` 字典加一张表 + `DISPLAY` 加显示名，按钮和时长自动出现。速度档位单调递增是性格词汇表：`creep(40) < hesitant(48) < probe(55) < cruise(70) < sprint(100)`，长冲刺只留给 startled（逃亡）和 excited（高潮）。

## 安全机制

1. 动画线程 `finally` 必发停机帧，带 5×0.1s 有限重试
2. `play()/stop()` 单飞锁，同时最多一个动画线程
3. 串口重连/断开时清空命令队列并补发 `X0/Y0`——防止断线期间堆积的旧运动命令重放到复位后的 UNO 上（交叉评审 P0 修复）
4. 串口 `timeout=0.1, write_timeout=1` + `join(timeout=5)`——防 USB 半死永久阻塞线程（旧版冻 Pi 的"放大器"）
5. STOP TRACKS 按钮 = `/track/stop`：立即停动画 + 停机

## 部署到 Pi

```bash
# Mac 上确认分支
cd walle-replica && git checkout track-xy

# 同步到 Pi（二选一; Pi 地址见工作区 IpList.txt, 仅实验室网络可达）
scp -r web_interface/{app.py,track_animations.py,static,templates} pi@<pi-ip>:<Pi上的工程路径>/web_interface/
#   或 Pi 上若为 git 克隆: git fetch && git checkout track-xy && git pull

# Pi 上重启服务并验证
sudo systemctl restart walle.service
#   浏览器打开网页 → 先跑 Calibration Run（抬轮或空旷地面）→ 再玩动画
```

首次验证清单：
1. 抬轮，Settings 确认串口已连接、**deadzone/死区补偿 = 0**（固件存在死区污染 bug，O>0 会导致电机自行加速——历史"X/Y 不稳定"的头号嫌疑）
2. Calibration Run（~26.5s）：直行走线直、自转 180°/90° 段角度准、贴身 180°、X40 慢行能动 → 标定有效
3. curious 完整跑完，结束时机器人停止端详（v2 结尾不再是冲刺）
4. 播放中点 STOP TRACKS：≤0.5s 停
5. 播放中推摇杆：**动画立即被抢占**，摇杆获得完全控制（v2 行为）

运维规则：
- **重启服务前先点 STOP TRACKS**（或确认无动画在跑）——停机兜底已三重化（动画线程 finally、`__main__` 退出钩子、atexit），`systemctl stop/restart`（SIGINT）路径会确定性发停机帧，但兜底只是兜底，先手动停是习惯
- 长时间连续跑 puppy/excited 后摸一下 L298 温度，热则停（满速段电流应力大）
